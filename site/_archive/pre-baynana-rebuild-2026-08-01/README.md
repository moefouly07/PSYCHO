# خريطة الذات والعلاقات

موقع ثابت (static) يضم **١٢ تقييمًا ذاتيًا إرشاديًا** بالعربية في مجالات الشخصية والعلاقات والانفعالات. يعمل بالكامل داخل المتصفح: بدون خادم، وبدون قاعدة بيانات، وبدون إطار عمل، وبدون مدير حزم، وبدون خطوة بناء.

- **١٢ اختبارًا** × **١٨ سؤالًا** × **٣ إجابات** = ٢١٦ سؤالًا و٦٤٨ إجابة.
- كل اختبار: ٦ أبعاد × ٣ أسئلة لكل بُعد.
- ٨ اختبارات تدعم مقارنة الشريك، و٤ فردية.

---

## بنية المشروع

```
index.html                      الصفحة الوحيدة (قشرة + وسوم SEO + التذييل)
assets/styles.css               كل الأنماط، وضعان فاتح وداكن، RTL
assets/app.js                   محرك الاختبارات: التوجيه، العرض، الحساب، المقارنة
data/tests.js                   تعريفات الاختبارات الاثني عشر (بيانات خالصة)
README.md                       هذا الملف
_archive/emotional-clarity-v2.html   النسخة السابقة ذات الاختبار الواحد (محفوظة)
```

لا توجد أي تبعيات خارجية، ولا `package.json`، ولا `vercel.json`.

## التشغيل محليًا

الملفات ثابتة، لكن `data/tests.js` و`assets/app.js` يُحمّلان عبر `<script src>`، وبعض المتصفحات تتشدد مع `file://`. الأضمن تشغيل خادم ثابت بسيط:

```bash
python -m http.server 5173
```

ثم افتح `http://localhost:5173`.

بديل بلا بايثون:

```bash
npx --yes serve .
```

فتح `index.html` مباشرة بنقرة مزدوجة يعمل أيضًا في أغلب المتصفحات، لكن الخادم المحلي أقرب إلى بيئة النشر.

## مخطط تعريف الاختبار

كل اختبار كائن داخل مصفوفة `TESTS` في `data/tests.js`:

| الحقل | النوع | الوصف |
|---|---|---|
| `id` | نص | معرّف فريد بالإنجليزية. يدخل في الرابط وفي كود المشاركة ومفاتيح التخزين. **لا يُغيَّر بعد النشر.** |
| `title` | نص | العنوان العربي. |
| `short` | نص | وصف من سطر واحد يظهر في البطاقة. |
| `category` | نص | `self` أو `relationships` أو `skills`. |
| `minutes` | رقم | المدة التقديرية. |
| `partner` | منطقي | `true` لتفعيل مقارنة الشريك. |
| `instructions` | مصفوفة نصوص | تظهر قبل البدء. |
| `disclaimer` | نص | تنبيه خاص بالاختبار، يُدمج مع التنبيه العام. |
| `dimensions` | مصفوفة (٦) | تعريفات الأبعاد، بالترتيب المعروض. |
| `questions` | مصفوفة (١٨) | `{ id, dim, prompt, options }` و`options` ثلاثة `{ t, s }`. |
| `bands` | مصفوفة (٤) | النطاقات الوصفية `{ id, min, max, label, summary, strength, growth }`. |
| `notes` | مصفوفة (اختياري) | ملاحظات شرطية `{ when: [{dim, op, value}], text }`. |
| `extra` | نص (اختياري) | `attachment` أو `compatibility` لكتلة نتائج إضافية. |
| `extraConfig` | كائن (اختياري) | إعدادات الكتلة الإضافية. |

### تعريف البُعد

| الحقل | الوصف |
|---|---|
| `id` | يطابق حقل `dim` في الأسئلة. |
| `name` / `short` | الاسم الكامل، والاسم المختصر للرسم البياني. |
| `polarity` | `positive` = الأعلى أفضل. `negative` = الأعلى يعني مزيدًا من السمة غير المرغوبة، ويُعكس في المجموع. |
| `desc` | وصف مختصر. |
| `interp` | `{ low, developing, strong }` — يُختار حسب **المستوى الصحي**، فـ`strong` تعني دائمًا الحالة الأفضل. |
| `tip` | اقتراح عملي يظهر إذا صار البُعد أولوية تطوير. |
| `pair` | `{ gap, bothLow, bothHigh }` — نصوص المقارنة (مطلوبة فقط عند `partner: true`). |

> أسئلة كل بُعد تُستنتج من حقل `dim` في السؤال، فلا توجد قائمة معرّفات مكررة يمكن أن تتعارض.

## كيف تضيف اختبارًا جديدًا

1. افتح `data/tests.js` وانسخ أقرب اختبار موجود كقالب.
2. غيّر `id` (فريد) و`title` و`short` و`category` و`minutes` و`partner`.
3. عرّف ٦ أبعاد بمعرّفات فريدة داخل الاختبار، وحدّد `polarity` لكل بُعد.
4. اكتب ١٨ سؤالًا، ٣ لكل بُعد، وكل سؤال بثلاث إجابات بدرجات `0` و`1` و`2` بالضبط.
5. بدّل ترتيب الإجابات في المصدر (لا تجعل درجة `2` دائمًا الأخيرة)، واحرص ألا تكون الإجابة الأعلى دائمًا الأطول أو الأكثر «مثالية».
6. اكتب ٤ نطاقات بالحدود `0-39` و`40-59` و`60-79` و`80-100`.
7. إن كان `partner: true`، أضف `pair` لكل بُعد.
8. أعد تحميل الصفحة — يظهر الاختبار تلقائيًا في القائمة وفي التصفية والبحث. لا حاجة لتعديل أي ملف آخر.

للتحقق السريع من البنية:

```bash
node -e "global.window={};require('./data/tests.js');const T=window.APP_DATA.TESTS;console.log(T.length,'tests',T.every(t=>t.questions.length===18&&t.dimensions.length===6)?'OK':'BAD')"
```

## طريقة الحساب

لكل بُعد:

```
الدرجة الخام = مجموع درجات أسئلته الثلاثة        (0 … 6)
نسبة البُعد  = round(الخام ÷ 6 × 100)
```

المستوى الصحي (يُستخدم للترتيب واختيار نص التفسير):

```
المستوى الصحي = النسبة            في الأبعاد الموجبة
المستوى الصحي = 100 − النسبة      في الأبعاد السالبة
```

النتيجة الكلية بعد عكس الأبعاد السالبة:

```
المجموع المعدَّل = Σ (الخام للموجب) + Σ (6 − الخام للسالب)
النسبة الكلية   = round(المجموع المعدَّل ÷ 36 × 100)
```

- نسب الأبعاد **مستقلة** ولا يُشترط أن يكون مجموعها ١٠٠٪.
- درجات الإجابات (`0/1/2`) **لا تُعرض للمستخدم** في أي شاشة.
- النطاقات الوصفية: `0-39` محدود أو يحتاج تطويرًا، `40-59` في طور النمو، `60-79` جيد، `80-100` قوي. الصياغة العربية تختلف من اختبار لآخر.
- **هذه نطاقات وصفية للمنتج، وليست نقاط قطع سريرية ولا معايير سكانية.**
- كل بُعد مبني على ٣ أسئلة فقط، لذلك أي فرق أقل من **١٧ نقطة** يُعامل كضجيج ولا يُقرأ كترتيب حاسم.

## الخصوصية

- **لا يوجد أي طلب شبكة** في شيفرة الموقع؛ لا تُرسل الإجابات إلى أي خادم.
- لا حساب ولا تسجيل دخول ولا بريد إلكتروني.
- التقدّم والنتائج تُحفظ في `localStorage` تحت البادئة `mcr:` فقط:
  - `mcr:theme` — المظهر المختار.
  - `mcr:name` — الاسم الظاهر في المقارنة.
  - `mcr:progress:<testId>` — الإجابات الحالية وترتيب الاختيارات وموضع السؤال.
  - `mcr:result:<testId>` — درجات الأبعاد الستة بعد الانتهاء.
- مسح بيانات المتصفح يمحو كل ذلك.
- **كود المشاركة** يحتوي على: رقم النسخة، ومعرّف الاختبار، والاسم الظاهر، ودرجات الأبعاد الستة المجمّعة. **لا يحتوي على إجابات الأسئلة الخام.**
- الكود مُرمَّز بـ Base64URL لتسهيل النقل، وهو **غير مشفّر**: من يحصل عليه يستطيع فك قراءته. يجب مشاركته مع أشخاص موثوقين فقط، والموقع يذكر ذلك للمستخدم صراحة.
- عند استخدام رابط يحمل الكود، يوضع الكود في **جزء التجزئة (hash)** من الرابط ولا يوضع في `query string`.

## النشر على Vercel

### الطريقة الأولى: Vercel Drop (سحب وإفلات)

1. افتح <https://vercel.com/new> وسجّل الدخول.
2. اختر رفع مجلد (Deploy / Drop).
3. اسحب **محتويات** مجلد المشروع (وليس المجلد الأب): `index.html` و`assets/` و`data/` و`README.md`.
4. اترك كل الإعدادات كما هي:
   - Framework Preset: **Other**
   - Build Command: **فارغ**
   - Output Directory: **فارغ** (الجذر)
   - Install Command: **فارغ**
5. اضغط Deploy. الرابط يعمل خلال ثوانٍ.

### الطريقة الثانية: من GitHub إلى Vercel

```bash
git -C . add -A
git -C . commit -m "موقع خريطة الذات والعلاقات"
git -C . remote add origin https://github.com/<اسم-المستخدم>/<اسم-المستودع>.git
git -C . push -u origin main
```

ثم:

1. افتح <https://vercel.com/new> واختر **Import Git Repository**.
2. اختر المستودع.
3. الإعدادات: Framework Preset = **Other**، وBuild Command وOutput Directory وInstall Command **فارغة**.
4. Deploy. بعدها كل `git push` ينشر تلقائيًا.

لا حاجة إلى متغيرات بيئة ولا إلى `vercel.json`.

### GitHub Pages

يعمل أيضًا: Settings ← Pages ← Deploy from a branch ← `main` ← `/ (root)`. كل المسارات في المشروع نسبية، والتوجيه يعتمد على جزء التجزئة (`#/`)، فيعمل الموقع من مجلد فرعي مثل `https://user.github.io/repo/` دون تعديل.

بعد النشر، حدّث وسم `<link rel="canonical">` في `index.html` بعنوان النطاق الفعلي (يوجد تعليق `TODO` عنده).

## الحدود العلمية والقانونية

- جميع الاختبارات هنا **تقييمات ذاتية إرشادية أصلية** (evidence-informed original self-assessments). صيغت بنودها من جديد، واستُخدمت المفاهيم النفسية المنشورة كمرجع تصوّري فقط.
- **لم يُنقل أي بند حرفيًا** من أي مقياس منشور، ولا من نسخه العربية.
- هذه الأدوات **ليست**: تشخيصًا سريريًا، ولا اختبارًا طبيًا، ولا أداة مُقنَّنة أو مُصدَّقة، ولا بديلًا عن تقييم يجريه مختص مؤهل.
- النطاقات الوصفية أولية وُضعت لأغراض العرض، وليست نقاط قطع سريرية ولا معايير سكانية، ولم تُشتق من عينة.
- لا تُستخدم النتائج في قرارات علاجية أو وظيفية أو قانونية أو في تقييم شخص آخر.
- **لا توجد مصادر أو مراجع مذكورة في واجهة الموقع.** المفاهيم المستخدمة معروفة في الأدبيات النفسية، لكن لم تُدرج روابط لأنه لا يمكن التحقق منها أثناء البناء دون اتصال. راجع تعليق `TODO` في هذا القسم قبل إضافة أي مرجع، ولا تُضف مراجع غير محقَّقة.

### تنبيهات السلامة المدمجة

بعض الاختبارات تُظهر ملاحظات شرطية عند أنماط إجابات معينة (التصعيد في الخلاف، سلوك المراقبة في الغيرة، فقدان السيطرة في الغضب، النقد الذاتي الشديد، انخفاض التعافي مع تنظيم الانفعال). هذه الملاحظات:

- لا تُشخّص ولا تصف المستخدم بأي اضطراب.
- توضّح أن المراقبة والضغط والتهديد ليست أساليب علاقة بل أذى.
- توجّه إلى دعم مختص عند الحاجة، وتذكر أن سلامة من يتعرض للأذى تسبق أي إصلاح للأسلوب.
- توضّح أن المرونة النفسية لا تعني تحمّل بيئة أو علاقة مؤذية.
